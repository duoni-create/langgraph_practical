# 课程助教 Agent - 项目流程说明

## 一、项目概述

本项目是一个基于 **LangGraph** 的课堂演示项目，名为「课程助教 Agent」。

它的核心目的是演示 LangGraph 的 4 个入门概念：
- **State（状态）**：在节点之间流动和共享
- **Node（节点）**：每个节点只做一件事
- **Edge（边）**：根据意图走不同分支
- **Persistence（持久化）**：通过 `thread_id` 记住同一条对话

项目默认对接 **DeepSeek** 模型（通过 OpenAI 兼容接口），同时提供 `--mock` 离线模式，方便没网时也能完整演示图执行流程。

## 四、LangGraph 图详解（app.py）

这是项目的核心。图由 **7 个节点** 和 **条件边** 组成：

### 4.1 节点说明

| 节点名 | 职责 | 对应函数 |
|--------|------|----------|
| `analyze_question` | 分析学生问题，识别 **意图** 和 **主题** | `analyze_question()` |
| `retrieve_concept_context` | 为「概念讲解」类问题补充素材 | `retrieve_concept_context()` |
| `retrieve_compare_context` | 为「对比」类问题补充素材 | `retrieve_compare_context()` |
| `retrieve_practice_context` | 为「练习」类问题补充素材 | `retrieve_practice_context()` |
| `retrieve_project_context` | 为「项目实战」类问题补充素材 | `retrieve_project_context()` |
| `retrieve_summary_context` | 为「课堂小结」类问题补充素材 | `retrieve_summary_context()` |
| `answer_question` | 调用 LLM 生成最终答案 | `answer_question()` |

### 4.2 执行路径（控制流）

```
START
  │
  ▼
┌──────────────────┐
│ analyze_question │  识别 intent + topic
└────────┬─────────┘
         │
         ▼  条件边 route_by_intent
    ┌────┴────┬────────┬──────────┬─────────┐
    ▼         ▼        ▼          ▼         ▼
 concept   compare  practice   project   summary
    │         │        │          │         │
    ▼         ▼        ▼          ▼         ▼
 retrieve_ retrieve_ retrieve_ retrieve_ retrieve_
 concept   compare   practice   project   summary
 _context  _context  _context   _context  _context
    │         │        │          │         │
    └─────────┴────────┴──────────┴─────────┘
              │
              ▼
    ┌──────────────────┐
    │  answer_question │  调用模型生成最终答案
    └────────┬─────────┘
             │
             ▼
            END
```

### 4.3 条件路由规则

`route_by_intent` 根据 `state["intent"]` 决定走向：

| intent 值 | 走向节点 |
|-----------|----------|
| `concept` | `retrieve_concept_context` |
| `compare` | `retrieve_compare_context` |
| `practice` | `retrieve_practice_context` |
| `project` | `retrieve_project_context` |
| `summary` | `retrieve_summary_context` |

## 五、状态流转（state.py）

`TutorState` 是贯穿所有节点的共享状态，各节点读取它、写回更新：

```python
class TutorState(TypedDict):
    messages: list[AnyMessage]      # 对话消息（HumanMessage / AIMessage）
    intent: str                     # 当前问题意图
    topic: str                      # 当前问题主题
    context_blocks: list[str]       # 检索到的知识素材
    answer: str                     # 最终生成的答案
    llm_calls: int                  # 累计调用模型次数
    steps: list[str]                # 执行轨迹日志
```

**关键点**：
- `messages` 和 `steps` 使用 `Annotated[..., operator.add]`，表示新值会**追加**到旧值上
- 同一 `thread_id` 下的多轮对话，`messages` 会自动累加，实现记忆效果

## 六、知识库与意图识别（knowledge.py）

### 6.1 本地知识库 `TOPIC_LIBRARY`

预定义了 5 个课堂主题：
- `langgraph` - LangGraph 框架本身
- `state` - State 状态管理
- `node_edge` - Node 和 Edge 概念
- `checkpoint` - Checkpoint 持久化
- `langgraph_vs_langchain` - LangGraph 与 LangChain 对比

每个主题包含：标题、关键词、核心概念、生活比喻、对比说明、练习建议、项目建议、课堂小结、易错点。

### 6.2 意图识别 `detect_intent`

通过关键词匹配判断用户问题的类型：
- 含「总结/小结/归纳/概括/回顾/复盘/summary」→ `summary`
- 含「区别/对比/比较/vs/和」+ 同时提到 langgraph 和 langchain → `compare`
- 含「练习/题/作业/quiz」→ `practice`
- 含「项目/实战/demo/案例/搭建」→ `project`
- 默认 → `concept`

### 6.3 主题识别 `detect_topic`

通过关键词匹配分数，找出最相关的主题，无匹配时回退到默认主题 `langgraph`。

## 七、模型层（model.py）

### 7.1 配置 `ModelSettings`

```python
@dataclass
class ModelSettings:
    model: str = "deepseek-v4-flash"
    base_url: str = "https://api.deepseek.com"
    temperature: float = 0.2
    api_key: str | None = None
    mock: bool = False
```

配置优先级：**命令行参数** > **环境变量** > **默认值**

### 7.2 两种模型实现

| 实现类 | 用途 | 网络依赖 |
|--------|------|----------|
| `DeepSeekTutorModel` | 真实调用 DeepSeek API | 需要联网 |
| `MockTutorModel` | 返回固定结构的演示文本 | 完全离线 |

### 7.3 Prompt 设计

真实模型会构造如下提示词结构：
1. **SystemMessage**：设定角色（课堂助教）+ 风格要求（口语化、带比喻、带场景）
2. **History**：最近 4 条历史消息（实现上下文记忆）
3. **HumanMessage**：注入当前问题 + 意图 + 主题 + 知识素材，要求按固定格式输出

## 八、CLI 入口（cli.py）

提供两种运行模式：

### 8.1 `run` 模式 - 单轮问答

```bash
python -m langgraph_practical run \
  --question "请用生活化的比喻解释什么是 LangGraph" \
  --thread-id class-01
```

### 8.2 `demo` 模式 - 双轮演示

```bash
python -m langgraph_practical demo --mock
```

固定提两个问题，演示 **thread_id 的记忆效果**：
1. 「请用生活化的比喻解释什么是 LangGraph。」
2. 「那 State 和 Checkpoint 分别像什么？请顺便给我一个练习。」

第二轮能感知到第一轮的历史，体现持久化能力。

## 九、数据流完整示例

以用户提问 *"LangGraph 和 LangChain 有什么区别？"* 为例：

```
1. cli.py 接收问题，创建 app
2. app.invoke() 启动图执行，传入 messages=[HumanMessage(...)]
3. 【analyze_question 节点】
   - 提取问题文本
   - detect_intent() → "compare"
   - detect_topic() → "langgraph_vs_langchain"
   - 更新 state: intent="compare", topic="langgraph_vs_langchain", steps=[...]
4. 【条件边】intent="compare" → 走向 retrieve_compare_context
5. 【retrieve_compare_context 节点】
   - 从 TOPIC_LIBRARY 取 "langgraph_vs_langchain" 的 compare 素材
   - 更新 state: context_blocks=[...]
6. 【普通边】→ 走向 answer_question
7. 【answer_question 节点】
   - 提取问题 + 历史 + context_blocks
   - 调用 TutorModel.generate() 生成答案
   - 更新 state: messages 追加 AIMessage, answer="...", llm_calls+=1
8. 【普通边】→ END
9. cli.py 打印最终结果（intent、topic、trace、answer）
```

## 十、关键设计要点

1. **单一职责**：每个节点只做一件事（分析 / 检索 / 生成），便于课堂讲解
2. **条件分支**：通过 `intent` 实现不同问题类型的差异化处理
3. **状态累积**：`messages` 和 `steps` 使用 `operator.add`，支持多轮对话
4. **持久化记忆**：`InMemorySaver` + `thread_id` 让同一对话能继承上下文
5. **安全设计**：API Key 通过 `.env`、环境变量或参数传入，不硬编码
6. **离线演示**：`MockTutorModel` 保证无网络时也能完整运行图流程
